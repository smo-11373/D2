# Negative pole (floor) — bad Designer experience, v0

*The **floor**: the same three interaction forms done *badly* — the **failure modes to avoid**. A blind
run's UX layout is scored by **distance from this**; landing near any of these on a rubric dimension is a
strong negative signal. Anchored to the same inherited action aggregate and action IDs as the positive.*

## Pattern 1 — Review Stop (`A-013` / `A-010`) — done badly

D2 dumps the **full raw node output** — every field, in internal/technical terms — with **no summary and
no ranking**; he must read the wall to find what matters and **reconstruct "what changed" himself.**
There is **no default action** — he must respond item-by-item. It is **all-or-nothing** (the wall, or
nothing to drill into). And it stops him for a **low-leverage** node too.

*Failure modes: wall-of-text; no leverage-ranking; internal framing; no default; all-or-nothing; interrupts when not worth it.*

## Pattern 2 — Monitoring (`A-016/017/018`) — done badly

Status is **buried** — he must ask targeted questions to reconstruct it — **or** D2 **pushes routine
updates** that interrupt him. Progress/cost/health are **conflated** into one vague "status," or shown as
**raw logs** to parse. **No at-a-glance health**; he has to dig to discover an anomaly (deviation *not*
made visible).

*Failure modes: buried / push-spam; conflated cost-vs-health; raw logs; deviation not visible.*

## Pattern 3 — Clarification Request (`A-012`) — done badly

D2 asks **often, for things it could resolve itself** (low-leverage pings), **one at a time**, each
forcing context reconstruction. The ask is **raw and open-ended** ("what should I do here?") — no options,
no recommendation, no consequences — so **he** does the analysis D2 should have done.

*Failure modes: asks when not worth it; un-consolidated stream; raw/open-ended; no recommendation; Designer carries D2's burden.*
