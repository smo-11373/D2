# Role–Action Aggregate Catalog

*Product 1 of the Action-Aggregate node's output package (contract §1.1). The actions each recognized
role performs — merged, grouped by role, stable IDs, each row Source-cited within the namespace
(`sources.md`), each action and each role carrying a substantial description. Target = the common,
anticipable set (open-list; method §1).*

*Derived — nothing invented. Roles from Phase 5 Item 3 (Human Position First) + the layer model
(D2 → D1 → D0) + the glossary's catalog-role anchors. Actions from each role's job function and the
relevant phase items; the D1 Designer's set sub-split passive [P] / active [A] (method §1); each
downstream operational role walked through the position-derived depth frame (design-node-algorithm
step 2). `A-003` is retired and skipped.*

## Roles

| ID | Role | Relationship | Description | Source |
|----|------|--------------|-------------|--------|
| R-00 | D2 Designer | intrinsic | Builder of the D2 product itself (the constitution, method, rules, catalogs, and design-node modules); **not** a user of D2. Holds Designer-originated completion/clarification authority over D2's intentionally-open living sets. Meta layer — exists by definition of D2 being built. | glossary `d2-designer`; Phase 5 §Item 2 |
| R-01 | D1 Designer | intrinsic | The **primary and only user of D2** (Phase 1's "Designer"). Directs the evolution of an existing Predecessor D1 into a materially revised successor D1, using D2's tools. The one human whose authority and scarce attention the whole system serves; cannot be removed from the ecosystem. | Phase 1 §2; glossary `d1-designer`; Phase 5 §Item 3 |
| R-02 | Design Node Builder | intrinsic | The conceptual worker that builds a single Design Node within its governing contract — narrow relevant skill set, sufficiently bounded to work from its local context without broad project knowledge. Intrinsic to D2's design mechanism (the design tree / design node model). | Phase 5 §Item 3; Phase 4 §Item 2; glossary `design-node` |
| R-03 | D1 Programmer | default | Changes product code according to implementation specifications; realizes an understood design rather than reconstructing it. A conceptual position in the design-to-programming handoff that a given D1 project may or may not staff distinctly — a D2-provided default the D1 Designer can change. | Phase 5 §Item 3 |
| R-04 | D1 Technical Manager | default | Maintains and upgrades the technical D0 product package **within the established design, without changing product code** — adjusting governed parameters, running the required harness, updating release state, repackaging and distributing. A default cast member the D1 Designer can change per project. | Phase 5 §Item 3; RU-01; glossary `d1` |
| R-05 | D0 Operator | default | Performs routine operation and routine user-level monitoring of a deployed D0 product, within approved operating choices. A D0-facing default the D1 Designer configures for his product. | Phase 5 §Item 3; glossary `d0`, `user` |
| R-06 | D0 Technical Manager | default | Installs and technically maintains a particular D0 deployment, and gives the D0 Operator front-line technical support. Owns deployment-level configuration and health. A D0-facing default the D1 Designer configures for his product. | Phase 5 §Item 3; glossary `d0` |
